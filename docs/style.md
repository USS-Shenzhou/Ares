此文件以渐进方式规定了LLM编写项目代码的所有规范，涵盖从命名、大小写风格、内容排布直到方法提取、安全策略等全部内容。
渐进式意味着，文档内容是随着项目开发逐步完善的。文档内容越少，LLM就需要在实际编写前事无巨细地询问越多的内容。随着文档内容逐渐增加，LLM就可以减少需要新增的标准。

每条写入的内容都需要确认或者明确表达。LLM应该根据指令随时写入、修改，但不得自行无根据地总结添加。

文档本身没有元标准。LLM允许在下方自行创建多级标题。

本文件的以下内容允许LLM修改。

# 暂存区

想起来的什么规范就可以放在这里。LLM可以在读到后顺手给这些内容进行整理归类，从暂存区移至本文档的其他章节。

# 通用

- 遵循全局claude.md中的规范
- 除非确实需要阻止某个实际存在（而非假想）的对象继承，否则不加`final`。
- 不写私有的空构造函数。

# 命名

- 大小写还是下划线：使用常规的java命名
- 禁止在类名、类名后缀和包名中使用`POJO`/`Pojo`。
- 类名直接使用其表示的事物名称，不添加`Definition`等后缀。例如，表示枪械属性的类就是`GunAttribute`。
- 以er结尾的类名：
    - `Helper`表示无状态工具类，不应被实例化，所有内容都是`static`。这类工具类即使名字不以er结尾，也命名为`Helper`，例如`AttributeIds`应为`AttributeIdHelper`。
    - 有状态的类，如果不需要实例化或者是单例，命名为`Manager`。
    - 有特化名称（如`Modifier`、`Serializer`）时，优先使用特化名称。
    - `Parser`只能用于有状态且需要实例化的类。

# 日志

- 不使用`LOGGER`，总是使用`LogUtils.getLogger()`。

# 注释

- 除非复杂逻辑或长方法且经过许可，否则不允许任何注释。使用英文写注释。
- javadoc注释：使用javadoc markdown风格，而不是传统javadoc格式。
- 不为类、字段、对象等等编写说明性注释，名称应当是自注释的。
- 除`TODO`和`FIXME`外，IDEA 还配置了`NEEDCHECK`和`NEEDTEST`两个待办标记，可按需使用。

# 空安全

- 空安全：优先使用javax.annotation包中的Nonnull和Nullable。除非特殊情况，不要主动写Nonnull。写Nullable要有依据（通常是被迫传染）。不主动使用optional，除非是进行函数式编程。如果MC或者其他依赖库传来了optional，除非下游也需要，或者拆掉后还得组装，否则尽快拆掉。
- `@Nullable`/`@Nonnull`注解：除形参、record组件等写在括号参数列表里的位置外，都写在被注解声明（方法、字段、局部变量等）的上一行。

# 单端代码

NeoForge已禁止任何形式的OnlyIn。约定通过包名client或者类名后缀C/S以示区别。
