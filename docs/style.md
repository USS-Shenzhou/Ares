此文件以渐进方式规定了LLM编写项目代码的所有规范，涵盖从命名、大小写风格、内容排布直到方法提取、安全策略等全部内容。
渐进式意味着，文档内容是随着项目开发逐步完善的。文档内容越少，LLM就需要在实际编写前事无巨细地询问越多的内容。随着文档内容逐渐增加，LLM就可以减少需要新增的标准。

每条写入的内容都需要确认或者明确表达。LLM不得自行总结添加。

文档本身没有元标准。LLM允许在下方自行创建多级标题。

# 暂存区

想起来的什么规范就可以放在这里。LLM可以在读到后顺手给这些内容进行整理归类，从暂存区移至本文档的其他章节。

- 遵循全局claude.md中的规范
- 大小写还是下划线：使用常规的java命名
- 空安全：优先使用org.jspecify.annotations包中的NonNull和Nullable。除非特殊情况，不要主动写NonNull。写Nullable要有依据（通常是被迫传染）。不主动使用optional，除非是进行函数式编程。如果MC或者其他依赖库传来了optional，除非下游也需要，或者拆掉后还得组装，否则尽快拆掉。
- 除非复杂逻辑或长方法，否则不允许注释。使用英文写注释。
- 单端代码如何分离：碰到了再说。
